## 2. Recommended changes (display-only unless marked)

### Details, after (content order)
1. **Header:** name, ticker, Reported + Sample badges, one date line. "Next: Q3 FY2026 · Thu, Oct 22" with the session moved to the reminder sheet (D4-07, keeps facts).
2. **Takeaway card (merged with EPS, D4-01):**
   - quarter, then the headline and badge;
   - **Reported · Estimate · Surprise** in one metric row;
   - the explanation;
   - a collapsed "EPS details", holding Difference, Basis and the lesson link.
   - The separate EPS card is removed on Details. Results keeps the full EPS card.
3. **Revenue card (D4-02):**
   - Reported · Estimate · YoY;
   - QoQ as a caption line ("+4.2% vs last quarter · can reflect seasonality") instead of a two-column row;
   - the no-estimate reason as one caption.
   - At large text, the metric grid uses the existing `rowsWhenNarrow` mode (aligned label/value rows instead of three stacked blocks), which roughly halves the height without shrinking text.
4. **Reaction:** unchanged (already compact).
5. **Insights (D4-04):** compact rows inside one card (icon, title, chevron), with the explanation behind "Show details" (the existing `StockInsightCard.details` toggle). It shows at most 3. The server text is unchanged.
6. **History (D4-05):** add 3 y-axis labels (max, mid, min of the shown reported + estimate values, formatted with the row currency through `EarningsFormatter.eps`). No new data: they are the min and max already used to scale the chart. Quarter labels: every label when they fit at the measured width (shared rule), else first/middle/last.
7. **Learn:** unchanged rows.
8. **Notes (D4-03, D4-06):** the same collapsed "Sources and disclosures" as Results. The sample note stays inside it, and the Sample badge stays in the header.

### Results, after
1. **Header (R4-03):** company row, then the title as "Q2 FY2026 results" at `sectionTitle`, then one period line. The publication time stays in the disclosures.
2. **EPS:** as now (it is the detailed screen).
3. **Revenue (R4-02):** Actual · Estimate · YoY, with a QoQ secondary row ("Previous quarter C$4.28B · +4.2%"). The QoQ explanation folds under "About these comparisons", and the separate QoQ card goes away.
4. **Reaction (R4-04):** keep the numbers and chart; the server explanation moves into "How to read this".
5. **StockSteps+ (R4-05):** MOCK scenario chips move into the existing grouped ⋯ scenario pattern (Portfolio `PortfolioScenarioGroups`), or are left as is (decision 5D4-4).
6. **Learn and disclosures:** unchanged.

### Copy (R4-01, D4-04): owner decision 5D4-2
Option A (recommended): keep the server sentences. **Display** only their first sentence, with the rest behind "Show details". There is no server or contract change and
nothing is lost. Option B: shorten the generated sentences in core (`EarningsResultsCalculator`, `EarningsInsightEngine`). That changes server output, so it would be a
separate phase with tests for the "doesn't guarantee the price" qualification.

## 3. Components
- **Reused:**
  - `StockMetricGrid(rowsWhenNarrow = true)` — already used by Portfolio, the one-decision-per-group rule;
  - `StockInsightCard(details = …)`;
  - `EarningsDisclosure` and `EarningsKeyMetrics` (5D.3);
  - `StockTrendChart(yLabels = …)` — the parameter already exists, Details passes an empty list today.
- **New, shared display only:** `EarningsDisplay.firstSentence` (split on the first ". " not inside a number), `historyYLabels(values, currency)`, and the
  `qoqCaption` string. No new UI components.

## 4. Files likely to change
- core: `earnings/EarningsPresentation.kt` (y labels, QoQ caption; display only).
- shared: `presentation/earnings/EarningsDisplay.kt`, `EarningsComponents.kt`, `EarningsScreens.kt`; tests.
- iOS: `EarningsScenes.swift`, `EarningsComponents.swift`.
- Not touched: server, calculations, the API, AI, entitlements, reminders, navigation.

## 5. Parity risks
- `rowsWhenNarrow` exists on both platforms (Portfolio uses it on iOS too), so it's low risk.
- iOS `EarningsHistoryChart` has its own axis drawing; y labels must be added there separately.
- The first-sentence split must be shared in Kotlin (not re-implemented in Swift).

## 6. Accessibility and regression plan
- **Unit tests:**
  - `firstSentence` never splits "C$1.94" or "3.0%";
  - y labels come only from existing values and are empty when fewer than 2 are reported;
  - missing values never become 0;
  - the merged takeaway keeps every EPS line (the key + collapsed set equals the old card lines);
  - every Details/Results note appears once inside the disclosures;
  - each layout rule decides once per group.
- **Devices:**
  - Android 360 dp at 1.0×/1.3×/2.0× in light and dark: measure the Details and Results screen heights against the 5D.3 captures;
  - iOS Large/AX3/dark once input works.
- Collapsed sections announce Expanded/Collapsed; the "Show details" toggles stay separate accessibility elements.
- TalkBack/VoiceOver stay NOT VERIFIED unless requested.
