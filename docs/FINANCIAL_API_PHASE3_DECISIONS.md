# Financial API — Phase 3 decisions requiring project-owner approval

Each item: recommended default, alternatives, consequences. Nothing here is implemented.

| # | Decision | Recommended default | Alternatives | Consequences |
|---|---|---|---|---|
| D1 | **Public API client identity** | Verify the deployed topology (direct `run.app` vs external load balancer), then trust only the Google-appended `X-Forwarded-For` hop(s) via a configured hop count; add Firebase App Check for app traffic | App Check only; sign-in for all provider routes; server-issued anonymous session tokens | Without it, IP limits behind Cloud Run likely key on the proxy (all users share a bucket). App Check needs client SDK work on Android and iOS. |
| D2 | **Rate-limiting policy** | Layered: per-route global budgets per instance (cheap, identity-free) + per-client limits once D1 is done + sign-in required for AI explanation routes (article insight, movement narration) | IP-only; identity-only; no public limits | Global budgets protect cost immediately but can degrade service for everyone during abuse; per-client limits need D1. |
| D3 | **Persistent / shared cache licensing** | Ask FMP and Finnhub in writing whether caching and serving their data to multiple end users, persisting it (Firestore/Storage), and precomputing derived screener values is permitted, and for how long | Stay process-local only | Process-local reuse is today's behaviour. Any L2, snapshot or bulk-derived product waits for this. |
| D4 | **Cross-instance coordination** | No new infrastructure now; tune Cloud Run (min/max instances, concurrency) and measure `ProviderCalls` / `cache.*` metrics for 2–4 weeks | Firestore L2 with leases; Memorystore; Cloud Storage for immutable statements | L2 adds per-read cost and complexity; Memorystore adds a fixed monthly cost and VPC connector. Worth it only if measured instance multiplication is material. |
| D5 | **Acceptable data staleness** | Quotes: provider timestamp always shown, until next open when closed; TTM ratios: 15 min open / until next open closed; statements: 24 h, ≤ 2 h near verified reports; stale fallback ≤ 2× TTL (statements ≤ 7 days) labelled "Not updated recently" | Keep current TTLs; shorter TTLs (more cost) | Longer closed-market TTLs cut requests with little user impact; stale fallback improves reliability but needs UI labels. |
| D6 | **Screener universe size and refresh** | Fix re-warm (mandatory); universe 3 × 100 with budget ≥ `U / T` (≈ 50/h per active instance) and 24 h refresh when closed — or 3 × 50 if cost must stay near today's peak | Smaller universe (≤ 100 total); on-demand only for market filters; precomputed snapshot (needs D3) | Today's low steady-state cost comes from a bug that empties financial screens. Restoring coverage costs ≈ 7,500/day/instance for 300 symbols with the proposed screener set (modeled). |
| D7 | **Infrastructure and provider spending** | Confirm FMP/Finnhub plan tiers, limits and bulk/batch endpoints; provide unit prices for dashboards; no new paid infrastructure in Phase 3 | Upgrade FMP plan for bulk endpoints; add Memorystore | Bulk endpoints could replace hundreds of screener requests per refresh if licensed; plan limits determine budget values. |
| D8 | **AI fair-use** (carried from Phase 1) | One durable StockSteps+ ledger with per-feature sub-limits | Separate durable allowances per feature | Prevents per-instance multiplication of AI allowances. |
